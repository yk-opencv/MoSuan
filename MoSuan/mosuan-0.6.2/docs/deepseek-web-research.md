# DeepSeek 网页版接口转发研究

研究日期：2026-11-03。范围：公开项目文档、部分关键源码及墨算现有接口的静态检查。

**结论：存在可供原型试验的实现，建议先用独立的 Node.js 本地代理验证，再为墨算增加显式的「网页版代理」连接方式。目前尚未安装、运行或登录这些代理，也没有完成真实网页版请求。**

## 1. 这条路线实际依赖什么

公开实现使用的是你自己的 DeepSeek 网页账号登录态，而不是开放平台的 API Key。代理在本机处理网页会话与回答流，再提供 `/v1/chat/completions` 一类兼容接口。

多个项目的代码采用相似流程：创建网页会话、请求网页协议要求的工作量证明（PoW）、提交问题、解析网页 SSE 回答流。网页流与现有 OpenAI 格式不同，包含快照、片段及追加/批量更新事件。需要正确区分回答正文与思考片段，不能简单拼接所有字符串。[客户端源码](https://github.com/sums001/Deepseek-API/blob/main/deepseek/client.py)

因此，仅把 `.env` 中的密钥替换为网页 Token，或只把域名换成 `chat.deepseek.com`，都不能接通。

这里的「免费」指走个人网页版服务，不使用开放平台计费接口；这不保证永久可用、无限请求或与官方 API 相同的服务质量。

## 3. 必须处理的上下文问题

这是此次研究中与墨算关系最直接的发现。

候选 Node 代理会依据 `x-agent-session`、`session` 或 `user` 标识选取会话；缺省时依据来源信息生成标识。已有远程会话时，它可能只追加新的消息。[会话选择与提示构造源码](https://github.com/dekrezz/FreeDeepseekAPI/blob/stable/server.js)

墨算目前向官方接口提交裁剪后的 `messages`，并不发送这些代理会话标识。如果直接转发，可能产生两种问题：不同笔记共用上游会话；用户把历史切为 0 轮时，上游仍记得先前消息。墨算的「最近 N 轮」就不再可靠。

原型默认应采用：**每次生成使用新的代理会话标识，仅提交墨算选中的完整历史与本次问题。** 这会增加网页会话数量，但语义清楚，能避免隐式上下文积累。需在实测中确认该代理确实为新标识创建独立的远程会话，并处理其本机会话缓存回收；不能只检查前端发出的 JSON。

## 4. 接入墨算的具体设计

以下为下一阶段建议，当前版本尚未实现。

- 保持 `/api/chat` 和前端 Markdown 阅读链路；在服务端增加 official / web-proxy 两种连接方式。现有服务目前写死官方域名，必须改代码，单改配置不能完成切换。
- web-proxy 只连接固定的本机地址，例如候选项目默认的 `127.0.0.1:9655`。代理独立运行，网页登录态只保存在其本地私有目录中；墨算不需要接收网页登录密码或把网页登录态传到前端。
- 网页版模式不使用 `DEEPSEEK_API_KEY`。若代理设置了本地访问密钥，应使用独立配置，避免误把官方密钥发给代理。
- 模型标识以代理实际返回的 `/v1/models` 为准，不能假定与当前官方模式的 `deepseek-chat` 通用。
- 用户明确选择连接方式。代理不可用、登录失效或协议变化时显示具体状态，不自动转向收费官方 API。
- 正文直接进入现有公式渲染链路。保留反斜杠、换行、代码块及原始公式定界符；不套用编程代理的工具调用修复逻辑。思考片段若返回，应与正文分离。
- 取消与超时贯穿浏览器、墨算、代理、上游连接。是否还需要调用网页的停止接口，必须用实际服务验证；「界面不再显示」不等于上游已停止生成。
- 代理上报的 usage 标为代理统计，除非核实来源与精度，不显示成官方精确 token 用量或费用。
- 首版只验证单账号、单并发的普通数学对话；不引入自动换号、批量请求或自动处理验证码。

## 5. 真实接通的验收步骤

1. 单独下载并固定候选版本，检查启动、登录、文件写入、网络目标及更新逻辑。先不连接墨算。
2. 由用户在专用本机浏览器窗口中自行完成登录及必要的人工验证。不要把账号凭据发到聊天中。
3. 验证代理状态、模型列表和一条简单问题。仅接口返回 200 不算成功，必须收到非空正文及明确结束事件。
4. 请求含中文、`\\frac`、四种数学定界符和代码块的回答，保存脱敏原始 SSE，检查转换前后正文逐字符一致。
5. 验证分段、思考/正文切换、正常结束、登录失效、限流、网络中断及停止生成；中断不能伪装为成功完成。
6. 使用两个笔记做隔离测试：A 中设置独有信息，B 不提供该信息；另测同笔记从多轮改为 0 轮，确认上游没有保留被排除的上下文。
7. 前述步骤通过后，接入墨算并运行现有回归测试，再增加代理模式下的保存恢复和长公式测试。
